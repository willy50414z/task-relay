Focus: delegation runtime hardening decisions, token cost, execution precision, and implementation risk

## 總結 Verdict

**整體方向可以採用，但目前不能全案 approve。**

`openspec validate harden-delegation-runtime` 通過，相關測試 `tests/test_quota.py`、`tests/test_output_verification.py`、`tests/test_packer.py`、`tests/test_worktree.py` 共 `32 passed`。但計畫文件與部分實作仍有幾個會影響安全邊界、delegate 執行精度、token 成本的問題。

最重要的結論：

- C1 review artifact existence/non-empty gate 可以 approve，但 primary 仍必須讀內容，不能只信非空檔案。
- C2 quota resilience 可以 approve，fast fallback default off 是正確成本取捨。
- C3 ephemeral worktree 方向正確，但文件矛盾必須修正：v1 應保留 headless `--dangerously-*` flags，隔離靠 worktree + push-disable。
- C4 packet generation 必須 revise：不要預設 inline 全 change；v1 應改成 deterministic scoped defaults + `--full-change-context` escape hatch。
- D5 dirty-tree guard 是必要項，尚未完成前 C3 不能視為完整。
- `delegent_review.md` / `delegation_review.md` / `delegate_review.md` 命名目前沒有全域一致，會造成 primary 找錯 artifact。

## C1: Review Output Verification

Verdict: **Approve with caveat**.

存在性 + 非空檢查是正確 v1。review path 沒有 `tasks.md` checkbox 作為 backstop，所以 delegate 只在 stdout 宣稱成功時，primary 可能完全沒讀到實際 findings。`--expect-output` 能用很低成本補上這個洞。

不建議現在導入 full `evaluate()` / `resolver` engine。review artifact 是 side-file contract，不需要 status-file protocol。導入 resolver 會增加概念負擔與實作面積，對 C1 的主要風險沒有同比例收益。

額外缺點與補救：

- 缺點：非空不代表內容正確。delegate 可以寫一行無效內容也通過。
- 補救：managed block 必須明確要求 primary 在採納前重讀 review artifact；`trly` 只負責 deterministic gate，不負責內容判斷。
- 可選加強：檢查最小 heading 或 severity marker，例如 `blocker / major / minor / suggestion` 至少出現其一。但不要讓這變成過重 schema。

## C2: Quota Resilience

Verdict: **Approve**.

把舊的 `288 × 300s` silent retry 改成 observable + bounded + classified retry 是必要修正。這不是 polish，是防止使用者以為 delegation 卡死。

fast fallback default off 是正確預設。quota-rejected calls 通常不會消耗該 agent token，但 fast fallback 會消耗 fallback agent 的 tokens，且 fallback agent 可能更貴。預設等待便宜 agent，讓使用者明確 opt in 切換，比自動燒更貴 agent 更合理。

額外缺點與補救：

- 缺點：hard quota default 仍可能等待到 30 分鐘。這降低等待體驗，但不增加 token。
- 補救：保留 `LLM_FAST_FALLBACK=1`，並在錯誤訊息中提示如何啟用。
- 後續建議：支援 per-mode policy。review 可以更快 fallback 或 fail，apply 可以更傾向等待便宜 agent，因為 apply 的 token/風險通常更高。

## C3: Trust Boundary

Verdict: **Revise before close-out**.

uniform ephemeral worktree + process-local push-disable 是正確 v1。它解決兩個最實際的風險：

- delegate 寫壞使用者真實 working tree。
- delegate 執行 `git push` 推到真實 remote。

不建議現在做 OS sandbox。OS sandbox 能提高安全性，但會引入 CLI 差異、模型 API 網路通行、credential/env 掛載、跨平台行為等問題。對目前 threat model「unreliable, not malicious」來說，worktree + push-disable 是更小、更可測的安全邊界。

必須修正的矛盾：

- `proposal.md` / `design.md` / trust-boundary spec 說 headless-execution flags 可以保留，因為移除會破壞 headless write。
- `tasks.md` 0.4 / 3.4 和 `design.md` Resolved Decisions #2 又說 drop all `--dangerously-*` flags。

審批建議：**以保留 dangerous flags 為 v1 正解**。理由是隔離目標不是阻止 CLI tool call，而是把正常寫入導到 ephemeral worktree，並用 env neutralize `git push`。若 drop flags 導致 `claude --print` 或 `codex exec` 不能 headless edit，delegation apply 會直接失效。

Residual risk 必須明確保留：

- delegate 仍可讀 `.env` 或其他本機檔案。
- delegate 仍可連網，因為 model API traffic 本身需要網路。
- 如果未來 threat model 變成 malicious delegate，才應升級到 OS sandbox 或 per-CLI sandbox profiles。

## D5: Dirty Working Tree Guard

Verdict: **Approve, but currently incomplete**.

stop-not-warn 是正確決策。ephemeral worktree 是 clean `HEAD` checkout，不會帶入 main working tree 的 uncommitted / untracked WIP。如果 main tree dirty 而 delegation 直接跑，delegate 會在 stale base 上工作。這不是安全問題，而是精度問題：patch 可能漏掉使用者剛改的上下文。

不建議 warn-only。warn-only 會讓使用者看到警告後仍然得到基於錯誤 base 的 patch，實際上沒有保護效果。

不建議自動 seed WIP 到 worktree。它會遇到 staged/unstaged/untracked/ignored files 的邊界問題，也可能把使用者不想暴露給 delegate 的 WIP 帶進去。

建議實作：

- `worktree.is_dirty(repo_root)` 用 `git status --porcelain` 檢查 staged、unstaged、untracked。
- `core.run_isolated(..., allow_dirty=False)` 在 `create_worktree` 前檢查，dirty 時 raise `DirtyWorkingTreeError`。
- CLI 加 `trly run --allow-dirty`，明確表示使用者知道 delegate 會從 clean `HEAD` 工作。
- 測試 dirty 時不建立 worktree/branch，dirty + allow-dirty 可繼續，clean 可繼續。

## Review Artifact Naming

Verdict: **Revise**.

目前名稱有三種：

- `spec/delegent_review.md`: `AGENTS.md` 與 `.codex/skills/task-relay-delegation/templates/review-proposal.md` 仍使用這個舊拼字。
- `spec/delegation_review.md`: packaged template 與 `task_relay/delegation.py` 已改成這個。
- `delegate_review.md`: 本次使用者要求寫入的審批檔名。

這會造成 C1 的 `--expect-output` contract 不穩定。review agent 可能寫 A，primary 卻檢查 B。

建議：

- 對 automated review artifact，統一使用 `spec/delegation_review.md`，因為它語意最清楚且已在 packaged runtime 中使用。
- 本檔 `openspec/changes/harden-delegation-runtime/delegate_review.md` 保留為人工審批補充，不作為 `trly run --expect-output` 的預設路徑。
- 同步更新 `AGENTS.md` 與 `.codex` skill template，避免舊拼字繼續傳播。

## C4: Packet Generation Scope

Verdict: **Revise before implementation is treated as complete**.

目前方向正確：generated packets 應該降低 delegate cold-start exploration，並標準化 context。問題是現行 shape 太寬：`trly pack` 目前會 inline `proposal.md`、`design.md`、`tasks.md` 和所有 delta specs。針對 task `6.1` 實測 packet 大小為 `31,650` bytes。這比缺 context 安全，但它削弱了原本 C4「精準 scoped reads」的主張，也可能消耗不必要的 delegate tokens。

Recommended implementation: **deterministic scoped defaults + full-context escape hatch**.

不要一開始就做完整 manifest-driven system。manifest 長期更乾淨，但在 packet variants 還不多之前，會先增加 artifact 維護成本和流程面積。

## C4 Reasoning Summary

目標是降低 token 使用，同時不要降低執行準確度。可選方案有三種：

1. **Current full-change inline**
   這最簡單也最穩，不容易缺上下文。但每個 delegate 都會拿到整個 OpenSpec change，即使任務很窄。這會增加 token，也會讓 delegate 注意到無關決策而過度實作。

2. **Manifest-driven scoped packet**
   這是長期理想架構。結構化 manifest 可以宣告精確檔案、heading、task slice，可測性高，也不需要 parse template 的自由文字。缺點是維護成本上升：使用者或模板作者必須同步維護 manifest。

3. **Deterministic scoped defaults**
   這是最佳 v1。packer 用本地 deterministic code 根據 mode/task 抽取小而穩定的 context，不需要 LLM 判斷 scope。這不增加 main-agent token，也避免過早引入 manifest。

## Recommended C4 V1 Design

`trly pack --mode <mode> --change <change> --task <task-id>` 預設應改成 scoped extraction：

- Inline `tasks.md` 的目標 task block，包含 parent heading；只有在需要編號脈絡時才包含 sibling tasks。
- Inline `design.md` 中 implementation 通常需要的 section：`Decisions`、`Risks / Trade-offs`、`Open Questions` 如果存在。
- 當 task heading 或 task text 命名 capability 時，只 inline 相關 capability spec。
- 如果無法判斷 spec relevance，保守 fallback 成 inline all delta specs，但要在 packet header 標記 fallback reason。
- `--read` 額外指定的檔案照樣 inline，無法 resolve 時 loud fail。
- 保留 `--out` 與 stdout 行為，讓 packet 繼續可被 `trly run --prompt-file` 消費。

新增 escape hatch：

- `--full-change-context`: 保留目前全量 inline 行為。
- `--dry-run --json`: 顯示會選哪些檔案/section、byte count、fallback reason，但不輸出完整 packet。

## C4 Token Cost Analysis

如果 scope selection 實作在 `packer.py` 裡，main agent token 不應增加。

壞流程：

```text
primary agent reads all proposal/design/spec files
primary agent decides what matters
primary agent writes a custom packet
delegate reads the packet
```

這會消耗 main-agent tokens，且重複推理。

建議流程：

```bash
trly pack --mode implementation-draft --change harden-delegation-runtime --task 6.1 --out /tmp/packet.md
trly run --target deepseek --prompt-file /tmp/packet.md
```

scope decision 是本地 deterministic code，只消耗 CPU 與 file I/O，不消耗 LLM token。delegate 收到的無關上下文比目前 full-change inline 少，因此總 token 應該下降。

## C4 Execution Precision Analysis

full-change packet 是 high recall、lower precision。它降低 missing context 的機率，但也讓 delegate 看到無關 tasks、resolved trade-offs、未負責的 spec，可能導致 over-implementation 或 touched adjacent scope。

scoped defaults 更適合 v1，因為它讓任務保持局部，同時保留最重要的全域 design sections。escape hatch 處理真的需要整個 change 的任務。

fallback 必須可見。如果 packer 無法把 task map 到特定 capability spec，而 fallback 到 all specs，packet 應包含：

```text
Scope note: capability relevance could not be resolved for task 6.1; included all delta specs.
```

這樣 primary 與 delegate 都知道 precision 已降級，而不是默默吃進大 context。

## Why Not Manifest First

manifest 是未來方向，但不是 C4 v1。原因：

- 它新增一種作者必須維護的 artifact。
- 它可能和 templates/tasks 分開 stale。
- 它在修掉目前 broad-inline 問題前，先增加實作面積。
- 如果 manifest selection 和 deterministic defaults 都在本地執行，manifest 不會額外降低 main-agent token。

只有出現以下情況時才應升級 manifest：

- 至少三種 packet modes 的 default scope 開始互相衝突。
- 多個 changes 需要無法從 task/spec 名稱推導的 custom scope。
- `packer.py` 開始累積脆弱 special cases。

## Concrete Task Amendments

建議修改 C4 tasks：

- 將「inline content from OpenSpec change artifacts per template placeholders」改成「inline deterministic scoped defaults per mode and task」。
- 新增 `--full-change-context`，明確保留目前 all-artifacts 行為。
- 新增 `--dry-run --json`，讓使用者看到 selection transparency 和 packet size estimate。
- 新增 tests：task-block extraction、design-section extraction、relevant-spec selection、fallback-to-all-specs note、full-context mode。
- 若短期不做 exact scoped reads，更新 C4 spec wording。不要在預設 all artifacts 時宣稱「exactly declared scoped reads」。

## Final Recommendation

此 change 應先修正以下項目再 close：

1. 統一 C3 文件：v1 明確保留 headless dangerous flags，隔離靠 worktree + push-disable；或明確改成 OS sandbox。不要兩者混寫。
2. 完成 dirty-tree guard 與 `--allow-dirty`。
3. 修正 C4 scope：v1 採 deterministic scoped defaults + `--full-change-context`。
4. 全域同步 review artifact 命名，避免 `delegent_review.md` / `delegation_review.md` / `delegate_review.md` 混用。

C4 最終建議：

```text
v1: deterministic scoped defaults + --full-change-context escape hatch
v2: manifest-driven scoped packets only if defaults become insufficient
```

這能保留「降低重複 token 消耗」的原始目標，同時讓實作保持小、可測、可回退。
